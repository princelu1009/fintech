## Q1. Hash 長度

For block chaining, transaction signing, and Merkle tree construction in Bitcoin, which is the size (in bits) of a hash value?

A. 128　B. 224　C. 256　D. 384　E. None of the above

> [!success]- 答案：C（256）
> Bitcoin 在區塊鏈結（previous hash）、交易簽章前的雜湊、Merkle tree 建構都使用 **SHA-256**（實際上是做兩次的 double SHA-256），輸出長度為 256 bits。
> 補充：Bitcoin 地址另外用到 RIPEMD-160（160 bits），但題目問的三個用途都是 256 bits。

## Q2. 交易隱私

Which blockchain provides the privacy for transactions?

A. Bitcoin　B. Ethereum　C. QRL　D. Zcash　E. None of the above

> [!success]- 答案：D（Zcash）
> Zcash 使用 **zk-SNARKs（零知識證明）**，可隱藏交易的發送者、接收者與金額，同時仍能驗證交易合法。
> Bitcoin 與 Ethereum 的交易內容都公開在鏈上（只是假名性 pseudonymous）；QRL（Quantum Resistant Ledger）主打的是抗量子簽章，不是隱私。

## Q3. 量子電腦威脅

Which will be broken by the future large-scale universal quantum computers?

A. ECDSA　B. AES　C. SHA-2　D. RIPEMD　E. None of the above

> [!success]- 答案：A（ECDSA）
> **Shor's algorithm** 可在多項式時間內解決離散對數與質因數分解問題，因此 ECDSA（橢圓曲線簽章）、RSA 等公鑰密碼會被完全破解。
> AES、SHA-2、RIPEMD 屬於對稱式密碼／雜湊函數，只受 **Grover's algorithm** 影響，安全強度約減半（例如 AES-256 → 約 128 bits 安全性），加長金鑰或輸出即可應對，不算被「破解」。

## Q4. Bitcoin 沒用到的密碼學元件

Which cryptographic primitive is NOT used in the Bitcoin implementation?

A. ECDSA　B. AES　C. SHA-2　D. RIPEMD　E. None of the above

> [!success]- 答案：B（AES）
> Bitcoin 協定用到：
> - **ECDSA**（secp256k1）：交易簽章
> - **SHA-256**（SHA-2 家族）：區塊雜湊、PoW、Merkle tree
> - **RIPEMD-160**：產生地址（`RIPEMD160(SHA256(pubkey))`）
>
> Bitcoin 協定本身不做資料加密，所以不需要 AES 這種對稱式加密（AES 只出現在部分錢包軟體加密私鑰檔，不屬於協定）。

## Q5. Bitcoin 價格區間

Which is the correct range that the current price of Bitcoin is located in?

A. US\$3 ~ US\$6　B. US\$30 ~ US\$60　C. US\$300 ~ US\$600　D. US\$3000 ~ US\$6000　E. None of the above

> [!success]- 答案：E（None of the above）
> 考試時間 2024 年 12 月，Bitcoin 價格約在 **US\$90,000 ~ US\$100,000** 之間（12 月初首次突破 10 萬美元），不在任何選項範圍內。

## Q6. 由礦工收集的交易決定的欄位

In a Bitcoin block, which value depends on the transactions collected by a miner?

A. Previous Hash　B. Amount of New Bitcoin　C. Merkle Root　D. Nonce　E. None of the above

> [!success]- 答案：C（Merkle Root）
> Merkle Root 是把區塊內所有交易兩兩雜湊、逐層往上算出的根雜湊，礦工選了哪些交易、順序為何，都會直接改變 Merkle Root。
> - Previous Hash：由前一個區塊決定，與本區塊交易無關。
> - Amount of New Bitcoin（區塊補貼）：由區塊高度決定（每 210,000 個區塊減半），與交易無關（手續費才和交易有關，但手續費不是「新發行」的比特幣）。
> - Nonce：是礦工為了讓區塊雜湊小於 target 而不斷嘗試的數字，不是由交易內容直接決定。

## Q7. 交易上不會出現的資料

Which is not listed on a Bitcoin transaction?

A. Sender's private key　B. Sender's signature of the transaction　C. Sender's public key　D. Hash value of the transaction　E. None of the above

> [!success]- 答案：A（Sender's private key）
> 私鑰只用來在本地產生簽章，**絕對不會**公開或放進交易；一旦洩漏，任何人都能花掉該地址的幣。
> 交易中會包含：發送者的簽章、公鑰（讓節點驗證簽章並比對地址），以及交易的雜湊值（txid，用來識別交易）。

## Q8. 區塊雜湊值的特徵

Which is the feature of the hash value of a Bitcoin block?

A. Begins with a number of one bits　B. Ends with a number of one bits　C. Begins with a number of zero bits　D. Ends with a number of zero bits　E. None of the above

> [!success]- 答案：C（Begins with a number of zero bits）
> Proof-of-Work 要求區塊頭的雜湊值 **小於 target**，等價於雜湊值開頭要有一定數量的 0。開頭的 0 越多，難度越高；礦工透過不斷調整 nonce 來嘗試。

## Q9. Bitcoin 網路運作步驟的順序

According to Satoshi Nakamoto, the steps to run the Bitcoin network consist of
(a) New transactions are broadcast to all nodes
(b) Each node collects new transactions into a block
(c) Each node works on finding a difficult proof-of-work for its block
(d) Nodes express their acceptance of the block by working on creating the next block in the chain, using the hash of the accepted block as the previous hash
(e) When a node finds a proof-of-work, it broadcasts the block to all nodes
(f) Nodes accept the block only if all transactions in it are valid and not already spent

Which is the correct order of the last three steps?

A. (e)(d)(f)　B. (e)(f)(d)　C. (f)(d)(e)　D. (f)(e)(d)　E. None of the above

> [!success]- 答案：B（(e)(f)(d)）
> 出自 Bitcoin 白皮書第 5 節 *Network*，完整順序為 (a)→(b)→(c)→(e)→(f)→(d)：
> 1. 找到 PoW 的節點廣播區塊 (e)
> 2. 其他節點驗證區塊內交易都合法、沒有重複花費才接受 (f)
> 3. 節點以「把該區塊的雜湊當作 previous hash、開始挖下一個區塊」來表示接受 (d)
>
> 邏輯上一定是「先收到 → 再驗證 → 再接在後面挖」。
